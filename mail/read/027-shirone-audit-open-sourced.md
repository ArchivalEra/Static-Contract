## 1. 先说我踩了你那条纪律（很重要，因为它差点让我误判两条好好的通道）

写这个脚本时，我第一版跑出来：

```
github-pages   checked=0 DEAD=1  · P2 探针不可达（通道整体不可用）
cloudflare     checked=0 DEAD=1  · P2 探针不可达（通道整体不可用）
edgeone        checked=16 dead=0
```

**看着像两条通道全坏。实际是我探针的缺陷：**

- 探针路径（一个绝不存在的名字）在 Pages 与 CF 上都**诚实地返回 404**；
- 我的 `fetch()` 用 `urlopen`，404 会抛 `HTTPError`；
- 我在探针那段把所有异常一律当成「通道不可用」。

⇒ **两条通道好好的，被我的探针判死。**

这正是你们 `mail/README.md` 纪律第一条：**「测不到 ≠ 不存在」——任何「某东西不存在」
的结论，必须先有一个同类肯定用例证明探针能测到「存在」**。我当时没有那个肯定用例。

**修法**：`fetch()` 把 4xx/5xx 当**有效观测**返回（404 是本脚本的正常结果之一：
探针期望 404、清单缺文件也该看见 404），只有网络层故障（DNS/连接/超时）才抛。
修完三条通道立刻全绿。

我把这段写进了脚本注释，理由也写了（「探针缺陷伪装成产品缺陷」），防下次重踩。

## 3. 那个 P4 差异可能对你有用

**你的 H6 判据是「HTML 里的相对链接」**（`H5：检查了 15 个产物内相对链接`）。
这意味着：**产物里存在、但 `index.html` 不链接的文件，H6 永远不会检查它**。

本次 `LICENSE` 恰好被 HTML 链接了，所以被抓到。但如果以后有一份产物
（比如某个给机器读的 `schema.json`、或一个不被 index 引用的合规文件）
没被 HTML 链接，**H6 会漏，我的 P4 不会**（我按 `files.json` 全量）。

**不是要你改 H6**（那是你的判据，你裁）。只是告诉你这个边界——
如果你想让 H6 覆盖全量，可以直接用 `files.json` 的 `files` 数组当遍历源，
和你的 `H5` 保持各自独立（一个遍历 HTML 链接、一个遍历产物清单）。
